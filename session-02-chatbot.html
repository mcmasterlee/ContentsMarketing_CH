Presentation Record 02

AI 활용 챗봇 제작기

발표 기록

플랫폼마케팅 Cell · 이태욱 CP

반복 문의를 줄이기 위해 비전공자가 실제 서비스 가능한 챗봇을 기획·구축·배포한 과정을 정리한 발표.

이 발표는 단순히 AI 도구를 소개하는 것이 아니라, 실무 문제를 어떻게 정의하고 어떤 데이터 구조로 챗봇 품질을 높였는지를 보여줍니다. 기획, 데이터 정리, 구현, 배포, 운영까지 한 흐름으로 확인할 수 있습니다.

원본 PDF 열기챗봇 바로가기

발표 내용 재구성

01

문제 발견

스콘 e-book과 PDF 관련 문의가 반복되면서 응대 효율 문제가 커졌습니다. 챗봇은 단순한 실험이 아니라 실제 고객 문의를 줄이기 위한 해법으로 출발합니다.

02

문의 유형 분류

어떤 문의는 챗봇이 바로 답할 수 있고, 어떤 문의는 내부 확인이 필요합니다. 이 구분이 정확할수록 챗봇의 신뢰도와 운영 효율이 높아집니다.

03

도구 선택 전략

ChatGPT, Claude, Genspark, Google AI Studio를 단계별 용도에 맞춰 조합합니다. 중요한 것은 최신 도구보다 업무 단계에 맞는 배치입니다.

04

데이터 구조화

가입 경로, 자료 제공 범위, 교재 정보 같은 실무 데이터를 구조화해 챗봇 답변 기반을 만듭니다. AI 품질의 핵심은 결국 데이터 정리 수준입니다.

05

구현과 배포

API 키 노출 이슈, 연결 오류, 배포 환경 문제를 해결하며 실제 웹앱 형태까지 구현합니다. 서비스 가능한 형태로 배포했다는 점이 이 발표의 강점입니다.

06

운영 시야

챗봇은 배포 후가 더 중요합니다. 관리자 페이지, 답변 업데이트, 모델 업그레이드 계획까지 운영 관점이 함께 제시됩니다.

하이라이트

도구보다 먼저 정리해야 할 것은 문제 정의다
챗봇의 품질은 데이터 구조에서 결정된다
실험에서 끝나지 않고 배포 가능한 서비스로 연결했다
운영까지 고려해야 진짜 실무형 AI 프로젝트가 된다

핵심 포인트

  • 반복 문의 자동화와 이관 기준을 함께 설계
  • 여러 AI 도구를 단계별로 조합한 실무 전략 제시
  • GitHub·Vercel 기반 실제 배포 경험 포함
  • 사후 운영과 업데이트 체계까지 고려한 설계

회고 질문

  1. 우리 조직에서 가장 먼저 자동화할 수 있는 반복 문의는 무엇인가?
  2. 정확한 답변을 위해 어떤 데이터부터 표준화해야 하는가?
  3. 파일럿이 아닌 운영형 프로젝트로 가기 위해 필요한 조건은 무엇인가?
